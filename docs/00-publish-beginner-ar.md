# نشر أكاديمية واشنطن خطوة بخطوة (للمبتدئين)

> **الحالة الصادقة:** لم يُنشر الموقع بعد، ولا يوجد رابط حقيقي. النشر يحتاج حساباتك أنت (GitHub وSupabase وVercel). كل الخطوات أدناه مجانية للتجربة. أسماء الأزرار قد تتغيّر قليلاً في مواقع الاستضافة.
> **مهم:** خطة Vercel المجانية (Hobby) **للاستخدام غير التجاري فقط**. استخدمها للتجربة، وقبل أن يدفع أي عميل انتقل إلى Vercel Pro وSupabase Pro (انظر `docs/06-costs.md`).

> **نتيجة المراجعة الأخيرة (15 أكتوبر 2026):** اختبارات الوحدة نجحت (85/85)، لكن تثبيت الحزم انتهى بمهلة ولم يتم التحقق من البناء أو فحص الأنواع أو ESLint. لا تنشر قبل نجاح هذه الفحوص على جهازك أو في GitHub Actions. لا يوجد `package-lock.json` بعد؛ أنشئه بتثبيت ناجح ثم ارفعه مع المشروع. التقرير التفصيلي في `docs/14-deployment-preflight-report-ar.md`.

## ما ستحتاجه
بريد إلكتروني، وكمبيوتر (الأسهل)، ونحو 45 دقيقة. لا تحتاج إلى كتابة كود. **مهم:** الحزمة لم يكتمل تثبيت حزمها أو بناءها في بيئة الفحص؛ قبل النشر اتبع فحص ما قبل النشر في `docs/14-deployment-preflight-report-ar.md`.

## الجزء 1 — GitHub (مخزن الملفات)
1. اصنع حساباً على github.com (Sign up) وأكّد بريدك.
2. اضغط **+** أعلى الصفحة ← **New repository**. الاسم: `washington-academy`. اختر **Private**. اضغط **Create repository**.
3. على جهازك: فُكّ ضغط ملف ZIP. افتح المجلد الداخلي `washington-academy` (الذي فيه `package.json`).
4. في صفحة المستودع اضغط **uploading an existing file**، ثم اسحب **كل محتويات** ذلك المجلد (وليس ملف ZIP نفسه). تأكد أن الملفات المخفية مثل `.github` و`.gitignore` و`.nvmrc` تُرفَع (على ويندوز: عرض ← إظهار العناصر المخفية؛ على ماك: Cmd+Shift+.).
5. انتظر انتهاء الرفع، ثم اضغط **Commit changes**.
6. لا ترفع أي ملف اسمه `.env.local` أبداً.

## الجزء 2 — Supabase (قاعدة البيانات وتسجيل الدخول)
1. اذهب إلى supabase.com ← **Start your project** وسجّل بحساب GitHub.
2. **New project**: اكتب اسماً، واخترْ كلمة سر قوية للقاعدة (احفظها)، واختر أقرب منطقة، ثم **Create new project** وانتظر دقائق.
3. من القائمة اليسرى افتح **SQL Editor** ← **New query**. من مجلد `supabase/migrations` على جهازك افتح الملفات **بالترتيب** 0001 ثم 0002 … حتى 0011: انسخ محتوى كل ملف كاملاً، الصقه، اضغط **Run**، وانتظر «Success». **توقف عند أول خطأ** وأرسل لي نصه ورقم الملف. لا تشغّل اختبارات SQL على قاعدة الإنتاج؛ استخدم مشروعاً تجريبياً منفصلاً.
4. من **Project Settings ← API** (أو ما يشبهه) انسخ إلى ملف ملاحظات خاص بك: **Project URL** و**anon public key** و**service_role key**. المفتاح الأخير سري جداً؛ لا ترسله لأحد ولا تضعه في GitHub.

## الجزء 3 — Vercel (الاستضافة والرابط)
قبل الضغط على Deploy، يجب أن يكون `npm install` و`npm run typecheck` و`npm test` و`npm run lint` و`npm run build` قد اكتملت بنجاح محلياً أو في CI. إذا لم تنجح، أصلح الخطأ أولاً. انتبه: Vercel Hobby مخصصة للاستخدام الشخصي غير التجاري؛ لا تستخدمها لإطلاق أكاديمية تجارية مدفوعة.
1. اذهب إلى vercel.com ← **Sign Up** ← **Continue with GitHub**.
2. **Add New… ← Project**، اختر مستودع `washington-academy` واضغط **Import**. سيتعرّف Vercel على Next.js تلقائياً؛ لا تغيّر إعدادات البناء.
3. افتح **Environment Variables** وأضف (الاسم ثم القيمة) هذه المتغيرات الأربعة كحدّ أدنى:

| الاسم | القيمة |
|---|---|
| `NEXT_PUBLIC_SITE_URL` | مؤقتاً `https://example.vercel.app` (نصحّحه في الخطوة 5) |
| `NEXT_PUBLIC_SUPABASE_URL` | Project URL من Supabase |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | anon public key |
| `SUPABASE_SERVICE_ROLE_KEY` | service_role key |

   وأضف أيضاً `CRON_SECRET` بنص عشوائي طويل (32 حرفاً فأكثر من أي مولّد كلمات مرور).
   متغيرات الدفع (Paymob) والبريد والفيديو **اختيارية** وتُضاف لاحقاً (انظر `.env.example` و`docs/10-paymob-setup-ar.md`). لا تخترع قيماً لها؛ اتركها فارغة حتى تحصل على المفاتيح الحقيقية.
4. اضغط **Deploy** وانتظر. إن فشل البناء، افتح سجل الأخطاء (Build Logs) وأرسل لي النص كاملاً.
5. عند النجاح سيظهر رابط يشبه `https://اسم-مشروعك.vercel.app`: هذا **رابطك الحقيقي**. انسخه، ثم **Settings ← Environment Variables** غيّر قيمة `NEXT_PUBLIC_SITE_URL` إلى رابطك، ثم **Deployments ← … ← Redeploy**.

## الجزء 4 — اربط Supabase بالرابط
في Supabase: **Authentication ← URL Configuration**: ضع رابطك في **Site URL**، وأضف في **Redirect URLs**: `https://رابطك/auth/callback`. (لا تفعّل CAPTCHA هناك: الكود لا يدعمه حالياً.) التفاصيل الكاملة في `docs/09-supabase-setup-ar.md`.

## الجزء 5 — أنشئ حساب المدير
1. افتح `رابطك/register` وسجّل بالبريد الذي سيكون للمدير، ثم أكّد بريدك من الرسالة. (الرسائل الافتراضية من Supabase محدودة؛ قبل الإطلاق الحقيقي اضبط SMTP خاصاً.)
2. في Supabase ← SQL Editor شغّل (بدّل البريد ببريدك):
```sql
update profiles set role = 'super_admin'
where id = (select id from auth.users where email = 'بريدك@example.com');
```
3. سجّل الدخول وافتح `رابطك/admin`.

## الجزء 6 — جرّب الموقع (من الموبايل أيضاً)
افتح الرابط على هاتفك وعلى الكمبيوتر وتأكد من: الصفحة الرئيسية، الدورات، التسجيل والدخول، لوحة `/admin`، إضافة دورة تجريبية، والدفع اليدوي. الدفع الإلكتروني لا يعمل حتى تضبط Paymob بمفاتيح **الاختبار** أولاً.

## إن تعثّرت
أرسل لي: رقم الخطوة، ولقطة شاشة أو نص الخطأ كاملاً. لا ترسل أي مفتاح سري.
