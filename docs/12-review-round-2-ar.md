## ما راجعته ولم أجد فيه مشكلة قابلة للإثبات
- ترتيب الترحيلات 0001→0011 (الأسماء بلا فجوات؛ التبعيات متأخرة الربط في plpgsql سليمة؛ 0005 تُسقط `create_order` القديمة قبل الجديدة؛ 0009 تضيف عموداً في نهاية `public_courses` فقط).
- توقيع Paymob: الحقول العشرون وترتيبها وثبات زمن المقارنة والتحقق قبل أي معالجة (مطابقة لما في التقرير الأول).
- سياسات RLS: الطلاب لا يكتبون في `orders/enrollments/payment_transactions`، المدرّس لا يغيّر السعر/الحالة (مشغّل `protect_course_fields`)، الأسئلة لا تُرسل `is_correct` للطالب، رفع الإيصالات داخل مجلد المستخدم.
- كل إجراءات الخادم الإدارية تعيد فحص الدور من قاعدة البيانات؛ `service_role` محصور في ملفات `server-only`.
- لا أسرار في الكود أو في `.env.example` (أسماء فقط).
- أُلحظ فقط (لم أغيّره): المدرّس يستطيع تعديل `access_days` و`pass_score` لدورته من نموذج التحرير (الحماية في قاعدة البيانات تشمل السعر والحالة والاسم المختصر لا هذين الحقلين). قرار عمل: إن أردت قصرهما على المدير فهو تعديل صغير.

## ج) ما لا يزال ناقصاً
1. **لم يُبنَ المشروع قط.** احتمال ظهور أخطاء أنواع/بناء مرتفع نسبياً لأن شيئاً لم يُصرَّف بالأنواع الحقيقية. كل تعديلاتي في TSX لم تُصرَّف أيضاً (فُحصت صياغتها فقط).
2. `next@15.5.21` و`eslint-config-next@15.5.21`: **لم أستطع التحقق من وجود هذا الإصدار في السجل.** إن فشل `npm install` بـ `No matching version` فغيّر الاثنين إلى أحدث `15.5.x` متاح (بنفس الرقم لكليهما). توافق React 19.2 وESLint 9 مع Next 15.5 صحيح على مستوى النطاقات المعلنة لكنه غير مُجرَّب.
3. `npm run lint` يشغّل `next lint` (مُهمَل في 15.5 وسيُزال في 16) مع إعداد flat؛ غير مُجرَّب. إن تعثّر فاستبدله بـ `eslint .`.
4. **الترحيل 0011 و`phase13_checks.sql` غير منفَّذين.** شغّلهما على مشروع Supabase **تجريبي** أولاً.
5. تكامل Paymob غير مُجرَّب بالكامل، وحقل `order.merchant_order_id` لم يُؤكَّد، والربط الأقوى برقم طلب Paymob الموقَّع (`order.id`) لم يُضَف عمداً (انظر `docs/10`).
6. سياسات Storage على Supabase الحقيقي، وتصميم الموبايل وRTL بصرياً، ولوحات الطالب/المدرّس/المدير على جهاز: لم تُفحص بصرياً (راجعت الكود فقط: `lang/dir` على `<html>`، خصائص منطقية `start/end`، أهداف لمس 44px، قائمة بلا JS).
7. لا يوجد `package-lock.json` (ينشأ بأول `npm install`؛ ارفعه).
8. تحذير Node عند الاختبارات (`Reparsing as ES module`) لأن `package.json` بلا `"type": "module"`؛ لم أغيّره لأن تأثيره على Next/Tailwind غير مُجرَّب.
9. حدّ الكوبون الأقصى يُفحص عند إنشاء الطلب لا عند الدفع (طلبات معلّقة متزامنة قد تتجاوز الحد قليلاً)؛ لم أغيّره.

## د) خطوات التشغيل والنشر بالتفصيل
**على جهاز بإنترنت (Node 22.18 أو أحدث، Git):**
1. فك الـ ZIP، ثم `cd washington-academy`.
2. `npm install` (ينشئ `package-lock.json`؛ **احتفظ به**). إن ظهر `No matching version` لـ `next` فاتبع البند ج-2.
3. `npm run typecheck` ثم `npm test` (يجب 85 ناجحاً) ثم `npm run build`. **أرسل لي أي خطأ يظهر نصاً كما هو.**
4. اختياري: `npm run lint` (استشاري).

**قاعدة البيانات (مشروع Supabase تجريبي أولاً):**
5. شغّل ملفات `supabase/migrations` من 0001 حتى **0011** بالترتيب (SQL Editor أو `DATABASE_URL=… bash scripts/run-sql-checks.sh --migrate`).
6. `DATABASE_URL=<اتصال القاعدة التجريبية> npm run test:sql` — يجب أن تنجح الملفات التسعة (ومنها `phase13_checks.sql` الجديد غير المُجرَّب؛ إن فشل فأرسل المخرجات).
7. على مشروع الإنتاج: نفس الترحيلات بعد أخذ نسخة احتياطية، ثم إعداد المصادقة وإنشاء المدير الأول (`docs/09-supabase-setup-ar.md`).

**النشر (بعد موافقتك):**
8. GitHub خاص ← رفع المشروع مع `package-lock.json` (CI يشغّل typecheck/test/build تلقائياً).
9. Vercel: استيراد المستودع، Node 22.x، ثم المتغيرات التالية (الأسماء فقط؛ القيم منك):
   `NEXT_PUBLIC_SITE_URL` (https بلا شرطة أخيرة؛ يُدمج وقت البناء فأعد النشر عند تغييره)، `NEXT_PUBLIC_SUPABASE_URL`، `NEXT_PUBLIC_SUPABASE_ANON_KEY`، `SUPABASE_SERVICE_ROLE_KEY` (سري)، `PAYMOB_SECRET_KEY`، `PAYMOB_PUBLIC_KEY`، `PAYMOB_INTEGRATION_ID`، `PAYMOB_HMAC_SECRET`، `PAYMOB_BASE_URL` (اتركه الافتراضي)، `CRON_SECRET` (32 حرفاً عشوائياً فأكثر)، واختيارياً: `CLOUDFLARE_STREAM_*` (3 متغيرات)، `EMAIL_PROVIDER_API_KEY`، `EMAIL_FROM`، `NEXT_PUBLIC_CONTACT_EMAIL`، `NEXT_PUBLIC_GOOGLE_ENABLED`، `CSP_ENFORCE`.
   تحقق قبلها: `node scripts/check-env.mjs --production --file <نسخة من القيم>` (لا يطبع القيم).
10. اربط Supabase (Site URL و`/auth/callback`) وPaymob (Transaction processed callback = `https://<موقعك>/api/webhooks/paymob`) ثم نفّذ دفعة **تجريبية** كاملة (`docs/10-paymob-setup-ar.md`) قبل أي بيع.
11. لا تفعّل `CSP_ENFORCE=1` إلا بعد فحص وحدة تحكم المتصفح.

## هـ) متطلبات خارجية عليك توفيرها
- جهاز بإنترنت لتشغيل `npm install/typecheck/build` (أو دفع الكود إلى GitHub ليشغّلها CI).
- حساب GitHub، حساب Vercel (Pro قبل أي دفع حقيقي)، مشروعا Supabase (تجريبي + إنتاج؛ Pro قبل الإطلاق).
- حساب تاجر Paymob (مفاتيح اختبار ثم حية، وإعداد رابط الإشعار) ودفعة تجريبية ناجحة.

- دومين للموقع، ومراجعة قانونية للسياسات (قوالب عامة لم يراجعها محامٍ).
- موافقتك الصريحة قبل أي نشر أو تعديل على قاعدة بيانات حقيقية (لم أنشر شيئاً ولم ألمس أي قاعدة بيانات).
