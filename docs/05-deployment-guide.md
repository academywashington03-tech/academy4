# دليل نشر المشروع على الإنترنت

> **لم يُنشر المشروع بعد، ولا يوجد رابط موقع.** هذا الدليل خطة تنفيذ؛ لا تعتبر أي خطوة ناجحة قبل أن تراها تعمل بنفسك.
> نفّذ الخطوات بالترتيب، ولا تدفع لأي خدمة قبل أن تصل الخطوة التي تطلب ذلك صراحةً.

## هل تصلح GitHub Pages؟ لا
GitHub Pages تستضيف **ملفات ثابتة فقط**. هذا التطبيق يحتاج خادماً: فيه 11 ملف إجراءات خادم و6 مسارات API و`middleware` و47 صفحة تعتمد على جلسة الدخول، ولا يمكن تصديره كموقع ثابت (`output: "export"` لا يدعم هذه الميزات). **استخدم GitHub لحفظ الكود وفحصه (CI) فقط، واستضف التطبيق على خدمة تشغّل Node/Next.js مثل Vercel.** نشر واجهة ثابتة بلا خادم يعني أنه لن يعمل دخول ولا دفع ولا دورات.

## خريطة المراحل
| المرحلة | الهدف | التكلفة |
|---|---|---|
| **أ. التجربة الخاصة** | موقع تجريبي بلا بيع حقيقي، للتأكد أن كل شيء يعمل | 0 (انظر قيد Vercel المجاني أدناه) |
| **ب. الإطلاق** | استقبال مدفوعات حقيقية | Vercel Pro + Supabase Pro (انظر [التكاليف](06-costs.md)) |

⚠️ خطة Vercel المجانية (Hobby) **للاستخدام الشخصي غير التجاري فقط** حسب سياسة Vercel. تجربة خاصة بلا بيع مقبولة، أما **قبول مدفوعات حقيقية من الطلاب فيتطلب خطة Pro**. اقرأ سياسة Vercel بنفسك قبل الإطلاق.

## الخطوة 1 — جهّز أسماء الحسابات (مجانية)
1. **GitHub**: github.com ← Sign up. ثم أنشئ مستودعاً **خاصاً (Private)** فارغاً باسم `washington-academy` (بدون README ولا .gitignore).
2. **Supabase**: supabase.com ← New project (اتبع [دليل Supabase](09-supabase-setup-ar.md)). احفظ كلمة مرور قاعدة البيانات في مدير كلمات مرور.
3. **Vercel**: vercel.com ← Continue with GitHub.

## الخطوة 2 — اختبر على جهاز كمبيوتر (مرة واحدة)
لا يمكن أن يتم هذا من الموبايل. استخدم أي كمبيوتر (ولو مستعار) فيه Node 22.18+ و Git:
```bash
npm install
npm run typecheck && npm test && npm run build
```
- إن نجحت الأوامر الثلاثة فالمشروع قابل للبناء فعلاً (لأول مرة). **إن فشل أي منها لا تكمل؛ أرسل لي النص.**
- ينشئ `npm install` الملف `package-lock.json` — **ارفعه إلى GitHub** (يجعل التثبيت مطابقاً دائماً).

## الخطوة 3 — ارفع المشروع إلى GitHub
أسهل طريقة بلا أوامر: **GitHub Desktop** (مجاني).
1. File ← Add local repository ← اختر مجلد المشروع ← «create a repository» ← Create.
2. تأكد أن قائمة التغييرات **لا تحتوي** `.env.local` ولا `node_modules` ولا ملف `.zip` (محجوبة تلقائياً بـ `.gitignore`). إن ظهر أحدها فتوقف وأخبرني.
3. Commit to main ← Publish repository ← فعّل **Keep this code private** ← Publish.
> رفع الملفات من متصفح الموبايل غير عملي (حد 100 ملف في المرة، والمشروع نحو 150 ملفاً، والـ ZIP لا يُفك تلقائياً).

بعد الرفع ستعمل فحوص `CI` تلقائياً (تبويب Actions). نجاحها = نجاح `typecheck` و`test` و`build` على خوادم GitHub. **هذا بحد ذاته دليل بناء حقيقي.**

## الخطوة 4 — قاعدة البيانات
اتبع [دليل Supabase](09-supabase-setup-ar.md) كاملاً: شغّل الترحيلات 0001 إلى 0011، اضبط عناوين المصادقة، وأنشئ المدير الأول. ثم افحص التخزين (3 مخازن).

## الخطوة 5 — النشر على Vercel (مرحلة التجربة)
1. Vercel ← Add New… ← Project ← اختر مستودع `washington-academy` ← Import.
2. Framework Preset: يُكتشف **Next.js** تلقائياً. اترك أوامر البناء الافتراضية.
3. Settings ← General ← **Node.js Version = 22.x**.
4. أدخل **متغيرات البيئة** (Settings ← Environment Variables ← Production). لكل متغير حدّد: أين تجده، وهل هو سري:

| المتغير | أين تجده | سري؟ | ملاحظة |
|---|---|---|---|
| `NEXT_PUBLIC_SITE_URL` | رابط موقعك النهائي (بدايةً رابط Vercel) | لا | **بدون** شرطة أخيرة، ويُدمج وقت البناء: غيّره ثم أعد النشر |
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase ← Project Settings ← API | لا | |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | نفس الصفحة (anon/public) | لا (مصمَّم للمتصفح) | حمايته عبر RLS |
| `SUPABASE_SERVICE_ROLE_KEY` | نفس الصفحة (service_role) | **سري جداً** | يتجاوز الحماية؛ لا يُكتب إلا في Vercel |
| `PAYMOB_SECRET_KEY` `PAYMOB_PUBLIC_KEY` `PAYMOB_INTEGRATION_ID` `PAYMOB_HMAC_SECRET` | لوحة Paymob ([الدليل](10-paymob-setup-ar.md)) | الثلاثة الأولى والرابع سرية عدا PUBLIC | مفاتيح **اختبار** أولاً |
| `CLOUDFLARE_STREAM_CUSTOMER_CODE` `…_SIGNING_KEY_ID` `…_SIGNING_KEY_PEM` | Cloudflare Stream | KEY_ID والـ PEM سريان | اختياري الآن |
| `EMAIL_PROVIDER_API_KEY` `EMAIL_FROM` | مزوّد البريد (Resend) | الأول سري | اختياري الآن |
| `CRON_SECRET` | تولّده أنت: نص عشوائي من 32 حرفاً فأكثر | **سري** | لمهمة البريد اليومية |
| `NEXT_PUBLIC_CONTACT_EMAIL` `NEXT_PUBLIC_GOOGLE_ENABLED` `CSP_ENFORCE` | اختياري | لا | انظر `.env.example` |

   تحقق قبل النشر على جهازك: `node scripts/check-env.mjs --production --file <نسخة من القيم>` (لا يطبع القيم).
5. اضغط Deploy. إن نجح فسيظهر رابط `.vercel.app`. **افتحه من موبايلك وجرّب قائمة الفحص أدناه.**
6. بعد معرفة الرابط: اضبط `NEXT_PUBLIC_SITE_URL` عليه ثم **Redeploy**.

## الخطوة 6 — اربط عناوين الموقع بـ Supabase و Paymob
- Supabase ← Authentication ← URL Configuration: Site URL = رابطك، و Redirect URLs تضم `<رابطك>/auth/callback`.
- Paymob: اضبط رابط الإشعار على `<رابطك>/api/webhooks/paymob` ([الدليل](10-paymob-setup-ar.md)).

## الخطوة 7 — الدومين (اختياري في التجربة، لازم للبريد)
اشترِ دومين من مسجّل تثق به، ثم Vercel ← Settings ← Domains ← أضفه واتبع تعليمات DNS. ثم حدّث `NEXT_PUBLIC_SITE_URL` وروابط Supabase وPaymob، وأعد النشر. البريد الإلكتروني للطلاب يحتاج دومين موثّقاً (SPF/DKIM) عند مزوّد البريد.

## الخطوة 8 — مهمة البريد اليومية
`vercel.json` يضبط مهمة يومية على `/api/cron/emails`. تعمل فقط عند ضبط `CRON_SECRET`. الخطة المجانية لـ Vercel تسمح بمهمة يومية فقط حسب التوثيق وقت الفحص؛ تحقق منها.

## قائمة فحص ما بعد النشر (من الموبايل)
علّم كل بند فقط بعد أن تراه يعمل:
- [ ] الصفحة الرئيسية تفتح بالعربية من اليمين لليسار على الموبايل.
- [ ] التسجيل بحساب جديد ثم تأكيد البريد ثم الدخول.
- [ ] الدخول بحساب طالب ثم محاولة فتح `/admin` تُظهر «ليست لديك صلاحية».
- [ ] أنت (المدير): أنشئ تصنيفاً ودورة ودرساً نصياً وانشرها.
- [ ] ارفع ملف PDF صغيراً لدرس وافتحه كطالب مسجّل (يجب أن يفتح)، ثم جرّب برابط مباشر بلا دخول (يجب ألا يفتح).
- [ ] سجّل طالباً في دورة مجانية وأكمل درساً ورأيت التقدم.
- [ ] دورة مدفوعة: الطالب لا يفتحها قبل الدفع.
- [ ] دفع Paymob **التجريبي**: يظهر الطلب «مدفوع» و«فُعِّل» في `/admin/orders` وتظهر الدورة عند الطالب.
- [ ] إعادة إرسال نفس الإشعار لا تنشئ اشتراكاً ثانياً (راجع سجل الطلبات).
- [ ] دفع يدوي: إرسال مرجع ثم اعتماده من حسابك.
- [ ] اختبار قصير وشهادة وصفحة التحقق العامة.
- [ ] تعطيل مؤقت لمفتاح البريد/الفيديو لا يُسقط الموقع.

## قبل قبول أي دفع حقيقي
- [ ] اجتازت كل بنود القائمة السابقة.
- [ ] نجحت اختبارات SQL على قاعدة تجريبية (`npm run test:sql`).
- [ ] ترقية Vercel إلى Pro (استخدام تجاري) و Supabase إلى Pro (نسخ احتياطية + بلا إيقاف تلقائي).
- [ ] مفاتيح Paymob **الحية** مع Integration حي، وإشعار حي مضبوط.
- [ ] سياسة الخصوصية والشروط والاسترداد: عدّل القوالب واحفظها من `/admin/settings` (إلى أن تحفظها تظهر بتنبيه «لم تعتمده الإدارة بعد»).
- [ ] تفعيل المصادقة الثنائية على GitHub وSupabase وVercel وPaymob وحساب البريد.
- [ ] `CSP_ENFORCE=1` بعد التأكد من خلو وحدة تحكم المتصفح من مخالفات.
- [ ] قارنت أول دفعات حقيقية بكشف Paymob يدوياً.

## التراجع عند مشكلة
- **الكود**: Vercel ← Deployments ← اختر نشراً سابقاً سليماً ← Promote to Production.
- **قاعدة البيانات**: الترحيلات تتقدم فقط. الاسترجاع يتم من النسخ الاحتياطية (تتوفر في خطط Supabase المدفوعة حسب صفحة الأسعار؛ تحقق منها).
