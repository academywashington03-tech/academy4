# قائمة اختبارات الوظائف والأمان

> **القاعدة:** لا يُعدّ شيء «ناجحاً» هنا إلا إذا **شُغِّل فعلاً وظهرت نتيجته**. ما لم يُشغَّل مذكور صراحةً مع السبب.
> **آخر فحص:** 14 أكتوبر 2026، في بيئة تطوير بلا إنترنت وبلا PostgreSQL وبلا `node_modules`.

## 2) ما لم يُنفَّذ (ومحجوب)
| الفحص | السبب |
|---|---|
| **البناء `next build`** | يحتاج `npm install` (إنترنت). **أول مهمة لك** |
| الفحص الحقيقي للأنواع | نفس السبب |
| **Lint** (`npm run lint` = `eslint .`) | مُهيّأ لكن **لم يُنفَّذ** (انظر docs/13) |
| **8 ملفات اختبار SQL (176 تأكيداً)** | لا PostgreSQL ولا Supabase هنا. **صفر منها شُغِّل** |
| اختبارات المتصفح `npm run test:e2e` | تحتاج موقعاً شغّالاً |
| اتصال Supabase / Paymob / Cloudflare / Resend الحقيقي | لا بيانات اعتماد ولا شبكة |
| فحص الجوال والشاشات | لا أجهزة (الشهادة فقط عُرضت) |
| اختبار الحمل وتحمّل الضغط | لم يُجرَ |

## 3) اختبارات القبول الثمانية عشر
✅ = شُغِّل ونجح · 🟡 = شُغِّل جزئياً (كود التطبيق فقط) · ⏳ = مكتوب ولم يُشغَّل (يحتاج قاعدة بيانات) · 🚫 = محجوب بحسابات/بيئة منشورة

| # | الاختبار | ما تحقق فعلاً | ما لم يتحقق |
|---|---|---|---|
| 1 | زائر يسجّل ويدخل | 🟡 التحقق من المدخلات، ولا يمكن تمرير حقل «role» | التسجيل الفعلي والبريد (🚫 Supabase) |
| 2 | الطالب لا يفتح صفحات الإدارة | 🟡 قواعد المسارات (اختبار وحدة) + فحص ثابت أن كل صفحة/إجراء إداري يتحقق من الدور | سلوك الموقع الحقيقي (e2e ⏳) |
| 3 | المدير ينشئ دورة وينشرها | ⏳ منطق شروط النشر مكتوب | تشغيل فعلي (🚫) |
| 4 | المدرّس يدير دوراته فقط | ⏳ `phase10_checks.sql` | لم يُشغَّل |
| 5 | إضافة درس وملف PDF | ⏳ التحقق من النوع والحجم (وحدة ✅) + سياسات التخزين مكتوبة | الرفع الفعلي (🚫) |
| 6 | الطالب يفتح دورة ويكمل درساً | ⏳ `phase5_checks.sql` | لم يُشغَّل |
| 7 | لا وصول لدرس مدفوع بلا اشتراك | ⏳ `rls_checks.sql` + `phase5_checks.sql` (سياسة قراءة الدروس) | لم يُشغَّل |
| 8 | حدث دفع «محاكى» لا يمنح اشتراكاً مدفوعاً | ✅ **إشعار بلا توقيع/بتوقيع مزيّف/بمبلغ معدَّل يُرفض (401) ولا يصل لقاعدة البيانات** (8 اختبارات) + فحص ثابت أن التحقق يسبق أي استدعاء للقاعدة. لا يوجد في الكود أي وضع دفع وهمي | الجانب القاعدي ⏳ |
| 9 | دفع حقيقي موثَّق يفعّل الاشتراك | 🟡 يُمرَّر المبلغ/الطلب من الإشعار الموقَّع للقاعدة | التفعيل داخل القاعدة ⏳، والدفع الفعلي 🚫 Paymob |
| 10 | إشعار مكرر لا ينشئ طلباً/اشتراكاً ثانياً | 🟡 رد 200 مع نتيجة `duplicate` على مستوى الإشعار | المنع داخل القاعدة ⏳ (`phase6_checks.sql`) |
| 11 | دفع فاشل/ملغى لا يمنح وصولاً | 🟡 يُمرَّر كفشل | القاعدة ⏳ |
| 12 | الدفع اليدوي واعتماده وتسجيله | ⏳ `phase7_checks.sql` | لم يُشغَّل |
| 13 | اختبار وعرض النتيجة | ⏳ `phase8_checks.sql` (تحليل نموذج السؤال ✅ وحدة) | لم يُشغَّل |
| 14 | الشهادة بعد استيفاء الشروط فقط | ⏳ `phase8_checks.sql` | لم يُشغَّل |
| 15 | صفحة التحقق من الشهادة | 🟡 صيغة الرقم (وحدة ✅)، عرض الشهادة ✅ | البحث في القاعدة ⏳ |
| 16 | لا طالب يقرأ/يعدّل بيانات غيره | 🟡 فحص ثابت: **RLS مفعّل على كل الجداول الـ27** | سلوك السياسات ⏳ (`rls_checks` و`phase10_checks`) |
| 17 | يعمل على الجوال والحاسوب | 🟡 تصميم متجاوب + شهادة A4 | e2e على أجهزة 🚫 |
| 18 | الموقع يعمل إن تعطل الفيديو/البريد | 🟡 بالتصميم: الدرس يعرض «الفيديو غير متاح مؤقتاً»، والبريد يتأخر دون كسر الدفع | تجربة فعلية 🚫 |

## 4) الفحوص الأمنية الآلية (ضمن `npm test` — ✅ ناجحة)
- عميل `service_role` لا يُستورد إلا في 5 ملفات خادم معتمدة.
- لا مكوّن متصفح يستورد وحدات الخادم (`server-only`).
- لا متغير سرّي يبدأ بـ `NEXT_PUBLIC_`.
- كل إجراء خادم يستدعي حارس صلاحيات (أو هو إجراء مصادقة عام معتمد).
- كل مسار API يتحقق من المنادي (جلسة أو HMAC أو سر المهمة).
- كل صفحة إدارية تتحقق من الدور، والتحقق لا يعتمد على الـmiddleware وحده.
- `dangerouslySetInnerHTML` محصور في موضعين مراجَعَين.
- كل التوجيهات من مدخلات المستخدم تمر عبر `safeNext`.
- تحديد المعدل مطبَّق على الدخول والتسجيل واستعادة كلمة المرور والتحقق من الشهادة والطلبات والكوبونات والدفع اليدوي.
- نسخة Next.js ≥ 15.5.21 وReact ≥ 19.2.1 (ثغرات أمنية معلنة في النسخ الأقدم).
- في SQL: كل دالة `SECURITY DEFINER` تثبّت `search_path`، وغير المقصود فتحها مسحوبة من العموم، والدوال الخاصة بالخادم مسحوبة من `authenticated` أيضاً، وRLS مفعّل على كل جدول، ولا منح صلاحيات جداول لـ anon.

## 5) اختبارات يدوية على الموبايل بعد النشر
اتبع «قائمة فحص ما بعد النشر» في [دليل النشر](05-deployment-guide.md). وأهمها: الطالب لا يفتح `/admin`، دورة مدفوعة مغلقة قبل الدفع، دفع Paymob التجريبي يفعّل مرة واحدة، وصفحة «نتيجة الدفع» وحدها لا تمنح شيئاً.

## 6) قائمة الأمان قبل الإطلاق
**مطلوب منك (لا يمكن للكود فعلها):**
- [ ] `npm run build` و`npm run typecheck` و`npm test` تنجح على جهازك وفي CI.
- [ ] `npm audit` بعد التثبيت، وتحديث Next.js لآخر تصحيح من الفرع 15 (`npm view next@15 version`)؛ 15.5.21 هي آخر نسخة تحققتُ منها لا بالضرورة الأحدث.
- [ ] `npm run test:sql` على مشروع تجريبي: كل الملفات الثمانية تنجح.
- [ ] مصادقة ثنائية على: GitHub وSupabase وVercel وPaymob وبريد المدير والبريد المرسِل.
- [ ] `SUPABASE_SERVICE_ROLE_KEY` وPaymob السريان وHMAC و`CRON_SECRET` في Vercel فقط، وتدويرها إن ظهرت في أي مكان.
- [ ] SMTP مخصص ودومين موثّق، قوالب البريد العربية في Supabase.
- [ ] **لا تفعّل CAPTCHA في Supabase** (الكود لا يدعمه).
- [ ] راقب وحدة تحكم المتصفح ثم اضبط `CSP_ENFORCE=1`.
- [ ] Vercel Pro وSupabase Pro قبل المدفوعات الحقيقية.
- [ ] راجع قوالب الخصوصية والشروط والاسترداد في `/admin/settings` (قوالب عامة مبنية على طريقة عمل المنصة، لم يراجعها محامٍ) وعدّلها واحفظها؛ تظهر بتنبيه «لم تعتمده الإدارة بعد» إلى أن تحفظها.
- [ ] مطابقة أول المدفوعات الحقيقية بكشف Paymob، ومراجعة `/admin/reports` أسبوعياً.
- [ ] سياسة احتفاظ وحذف بيانات مكتوبة (انظر دليل Supabase).

## 7) القيود والمشكلات المعروفة (بصراحة)
1. **لم يُبنَ المشروع ولم يُجرَّب بأي تشغيل حقيقي.** قد تظهر أخطاء بناء لا تُكشف إلا بالحزم الحقيقية.
2. **SQL غير مُشغَّل:** منطق الدفع والصلاحيات داخل القاعدة مكتوب بعناية ومُراجَع يدوياً لكنه غير مُنفَّذ. بعد التشغيل قد تظهر أخطاء.
3. **ربط إشعار Paymob بالطلب** يعتمد على حقل `order.merchant_order_id` ولم أتأكد منه (فشل آمن لو اختلف).
4. **CSP يعمل بوضع التقرير فقط** افتراضياً، ويسمح بـ`'unsafe-inline'` للسكربت (شرط Next.js بلا nonce).
5. **تحديد المعدل «يفشل مفتوحاً»** لو تعطل المحدِّد نفسه، حتى لا يُغلَق الطلاب خارج الموقع.
6. **إتمام الدرس يسجّله الطالب بنفسه**؛ لا يمكن التحقق من مشاهدة الفيديو كاملاً.
7. **الحماية من نسخ الفيديو محدودة:** الرمز المؤقت يمنع مشاركة الرابط لكن لا يمنع تسجيل الشاشة.
8. **لا CAPTCHA** (محدودية معروفة؛ تعتمد على حدود التطبيق وSupabase).
9. **رفع الفيديو يتم من لوحة Cloudflare** (لا رفع من التطبيق)، وعلى المدير تفعيل «Require signed URLs».
10. **الشهادة PDF من المتصفح** (طباعة/حفظ بصيغة PDF) وليست ملفاً يولّده الخادم.
11. **لا استرداد من داخل اللوحة ولا خصم تلقائي متكرر**؛ الاشتراكات فترات مدفوعة مسبقاً.
12. **الدفع اليدوي** يعتمد على مطابقتك البنكية؛ لا يستطيع النظام التحقق من حسابك.
13. المطابقة المالية داخلية (طلباتك مقابل عملياتك)، لا مقابل كشف Paymob.
14. **صفحات الخصوصية والشروط والاسترداد قوالب عامة** (لم يراجعها محامٍ)؛ سياسة الاسترداد لا تحدد مدة لأنها قرارك.
15. **Lint مُهيّأ (`eslint .`) لكنه لم يُنفَّذ بعد** (يحتاج `npm install`).
16. واجهة الإدارة بالعربية فقط (الواجهة العامة عربية/إنجليزية).
